# DeviceDeck 完整方案

状态：v0.1 首版；以个人设备管理验证需求，后续按真实使用反馈演进。

## 现状判断和必要性

已有 SSH 别名、专用密钥和跨工具 Skill，解决了“怎么连”。它们分别保存在 SSH 配置、技能清单和检查记录里；相同设备的局域网与远程地址依赖人工对应，历史可达性和当前状态容易混淆，移动设备的配对方式也没有共同模型。这是连接入口的统一，尚不是完整的设备管理。

现阶段值得做轻量的统一设备台账和连接观测层：一次登记，多入口使用；复用现有 SSH、ADB、iOS 工具；先在个人电脑运行。首版无需中央服务器、设备端常驻 Agent 或全网主动扫描。先证明日常能查清设备、选对入口并区分失败原因，再考虑自动化控制和多人协作。

现有项目有可借鉴基础：[NetBox](https://netboxlabs.com/docs/netbox/)面向网络建模、IPAM/DCIM 和自动化事实来源；[MeshCentral](https://meshcentral.com/)提供跨平台远程管理及设备 Agent。DeviceDeck 的首版定位是个人或小团队的设备身份、访问入口、认证元数据与 Agent 工具层；上述定位是设计判断，不代表已验证市场差异或需求规模。

## 核心模型

| 对象 | 负责内容 | 约束 |
|---|---|---|
| Device | 稳定 ID、名称、类型、预期身份、标签 | IP 或连接协议变化不创建另一台设备 |
| Endpoint | LAN/Tailscale/远程/USB、协议、IP/主机名、端口、账号、serial/UDID | 一个 Device 可以有多个入口；USB 不要求 IP |
| Credential profile | 认证类型、外部私钥路径、可选密码库引用 | 不保存密码、私钥内容、配对码或令牌 |
| Observation | 采集时间、连通结果、身份验证结果、系统/内存/磁盘指标 | 当前只验证被选入口；缺失指标为 unknown/null |
| Audit event | 谁通过哪个界面执行何种检查或登记、时间、结果 | 保存摘要，不保存完整命令输出或凭据 |

设备连接地址的来源可以是用户登记、已有 SSH 配置、Tailscale 设备列表或 USB 工具。来源记录和跨来源去重是下一阶段能力；首版由用户显式建立设备与入口关系，禁止因名字相似就自动合并。

## 可看到的信息

每台设备有局域网、远程或 USB 连接入口；同一台机器的入口展示在同一卡片。认证配置展示 SSH 密钥、SSH agent、密码登录、Android 配对、iOS 信任或 WDA 访问及其外部引用。状态区显示最近采集的系统版本、内存、磁盘、时间和已验证/未验证/失败原因。没有结果不能显示为零、在线或健康。

手机需要区别处理：Android 使用明确 serial 的已授权 ADB；iOS 使用明确 UDID 的可信 USB，或既有 WDA 的 HTTP 状态。iOS 信任电脑不代表自动获得 UI 控制；开发者设置、签名和 WDA 部署属于另外的用户操作。

## 用户流程与验收

1. 初次使用：安装应用 → 登记认证引用 → 登记设备及多入口 → 查看连接说明 → 用户在现有客户端完成首次信任/配对 → 手动检查指定入口。
2. 日常使用：按名称筛选 → 看最新观测时间 → 选择适合当前网络的入口 → 检查 → 查看系统状态。超时、拒绝认证、主机公钥变化、缺少客户端和需配对分别展示。
3. 变更：编辑原设备的 IP 或入口；身份仍由稳定设备 ID 和严格公钥/配对检查约束。SSH 别名与登记地址冲突时停止，不静默转到其他主机。
4. 凭据变更：在外部 SSH/密码库工具中轮换；更新认证引用并重新检查。不把原凭据传给 Agent。
5. Agent：Skill 负责流程与授权边界；MCP 返回结构化设备数据、连接方案和只读检查；它们与网页/CLI 使用同一 SQLite 数据。

首版验收：计算机/NAS/路由器已有入口可读系统状态；同一设备多个入口不会变成多台设备；密码 profile 返回明确的手动登录说明；移动适配器的固定命令及失败分支有测试；两种 Agent 客户端可以加载技能并调用 MCP；公开源代码不包含真实设备清单、私人地址、凭据或私钥。

## 架构与权限

Python 核心服务 + SQLite；FastAPI 本机网页；CLI；官方 MCP Python SDK 的本地 stdio 服务；可移植 SKILL.md。各界面调用同一 Service/Store/Adapter，不复制设备数据。

v0.1 只提供固定只读探测，不提供任意命令执行、屏幕点击、重启、刷机、自动配对或开放调试端口。网页只监听 127.0.0.1，并限制 Host、Origin 和跨站请求。设备台账在用户私有目录，密钥仍交给原客户端管理。数据库权限保护其他 OS 用户，但数据库元数据未加密；本地数据备份须按私人资料处理。

MCP 的 probe 会更新本地观测和审计，所以工具注解说明本地写入；远端操作仍是固定读取。注解是提示，实际限制由实现的工具边界执行。

## 路线图

| 阶段 | 内容 | 进入条件 |
|---|---|---|
| v0.1（已实现首版） | 本机登记、编辑、多入口、认证引用、检查、CLI/网页/Skill/MCP | 当前个人设备与核心协议验证通过 |
| v0.2 | SSH/Tailscale/USB 发现候选与人工去重、OS vault provider、凭据可用性、归档/恢复 | 实际使用明确了接入和状态漂移问题 |
| v0.3 | 有限频率刷新、告警、备份/导出、连接策略、可选原生移动工具桥接 | 正确区分外部服务状态与真实设备状态 |
| 后续 | 签名的可授权动作目录、权限/RBAC、认证远程 MCP/多人服务 | 风险动作可审计、授权与身份隔离完成 |

不承诺自动支持所有 NAS、移动系统或 SDK 版本。移动实机验证、设备发现去重、密码 vault 自动登录和远程多人服务，须分别完成对应验收才标为支持。
